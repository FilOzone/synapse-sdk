:::note[Preview]
Storage Providers are rolling out gated retrieval. A provider without it ignores `read: restricted` and serves the pieces publicly, so check that yours supports it.
:::

[Encryption](/developer-guides/encryption/encrypt-a-file/) controls who can *read* your data. Access control decides who can *fetch* it. A piece in a restricted data set is served only to a request carrying an `Authorization` header that proves the caller holds a grant reaching that piece.

Access is authorized with the same keyspaces, scopes and piece identifiers as encryption [grants](/developer-guides/encryption/share-encrypted-data/), so whoever can fetch a piece can also decrypt it, and nobody else can do either.

Gated retrieval is a weaker protection than encryption. It stops casual and bulk download, but a provider, or anyone who copies the data from one, still has the bytes. That's why every piece in a restricted data set must be encrypted.

## Create a restricted data set

Set the data set metadata `read` to `restricted` when you create it. Every piece added to it must be a [Filecoin encryption envelope](/developer-guides/encryption/encrypt-a-file/) starting at the first byte of the piece. The provider reads the envelope's `foc/*` labels to decide who may fetch it, and refuses to add anything else.

```ts twoslash
// @lib: esnext,dom
import { Synapse } from '@filoz/synapse-sdk'
import { privateKeyToAccount } from 'viem/accounts'

declare const encrypted: Uint8Array
const synapse = Synapse.create({ account: privateKeyToAccount('0x...'), source: 'my-app' })
// ---cut---
const context = await synapse.storage.createContext({ metadata: { read: 'restricted' } })
const { pieceCid } = await context.upload(encrypted)
```

Pieces in a restricted data set are served only from `/download/<pieceCid>`. They are not served from `/piece/<pieceCid>`, and their contents are not indexed for IPFS retrieval.

:::caution
Upload the envelope itself. A piece that wraps the envelope in something else, such as a CAR file, has no labels where the provider looks, so it is refused.
:::

## Give a reader a claim chain

To fetch, the reader needs a **claim chain** as well as a key: a chain of signed links from the data owner's wallet to the reader's address, naming what it covers and when it expires. The provider checks the chain on every request, so nothing is registered on chain or with the provider.

The owner signs a root claim to the reader and sends it together with the key as a single **delivery**. The Filecoin Pay Console does this for a session key on `filecoin-pin login`.

```ts twoslash
// @lib: esnext,dom
import * as Keysmith from '@filoz/keysmith'
import type { Address, Hex } from 'viem'

declare const wallet: Keysmith.ClaimSigner
declare const ref: Keysmith.KeyspaceRef
declare const keyspaceKey: Uint8Array
declare const reader: Address
declare const readerPublicKey: Hex
// ---cut---
const { chain, nodeKey } = await Keysmith.rootClaim(wallet, {
  ...ref,
  chainId: 314159n, // calibration
  kk: keyspaceKey,
  node: 'scope:agent-memory',
  bearer: reader,
  maxDepth: 0, // 0: the reader cannot delegate it onward
  expires: Math.floor(Date.now() / 1000) + 7 * 86400,
})
const delivery = Keysmith.encodeDelivery(
  chain,
  await Keysmith.wrapTo(readerPublicKey, nodeKey, Keysmith.grantDescriptor(ref, 'scope:agent-memory')),
)
```

A reader with `maxDepth` above 0 can pass a narrower scope on with `delegateClaim()`, adding a link to the chain. The provider checks that each link is no wider than the one before it.

## Fetch with the Authorization header

The reader opens the delivery, signs a request for one piece, and sends it with its chain as `Authorization: FOC-Grant <base64url>`:

```ts twoslash
// @lib: esnext,dom
import * as Keysmith from '@filoz/keysmith'
import type { PieceCID } from '@filoz/synapse-sdk'
import type { Hex } from 'viem'
import { privateKeyToAccount } from 'viem/accounts'

declare const readerPrivateKey: Hex
declare const delivery: Uint8Array
declare const pieceCid: PieceCID
declare const serviceURL: string
// ---cut---
const { chain, key, grant } = await Keysmith.openDelivery(readerPrivateKey, delivery)

const request = await Keysmith.signRequest(privateKeyToAccount(readerPrivateKey), chain, {
  pieceCid: pieceCid.bytes,
  expires: Math.floor(Date.now() / 1000) + 240, // at most 5 minutes ahead
})
const header = `FOC-Grant ${base64url(Keysmith.encodePresentation(chain, request))}`

const response = await fetch(`${serviceURL}/download/${pieceCid}`, { headers: { Authorization: header } })
// Decrypt the body with Keysmith.keyResolver(key, grant), as for any encrypted piece

function base64url(bytes: Uint8Array): string {
  let binary = ''
  for (const byte of bytes) binary += String.fromCharCode(byte)
  return btoa(binary).replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '')
}
```

A header names one piece and expires within five minutes, so make a fresh one for each fetch. Until it expires, the same header also works for `Range` requests and at any provider holding the piece.

### What the provider checks

The provider refuses the request unless all of these hold:

* Every link is signed: the root by the owner, and each later link by the bearer before it.
* The chain has not expired, and names the provider's network.
* Each link is no wider than the one before it, and within its `maxDepth`.
* The request names this piece, has not expired, and is signed by the chain's final bearer.
* The piece's `foc/own` and `foc/ks` labels name the chain's owner and keyspace.
* The final link reaches the piece: the keyspace, a scope containing the piece's `foc/scope`, or the piece's own `foc/salt`.

| Response | Meaning |
| --- | --- |
| `200` / `206` | Served. |
| `401` with `WWW-Authenticate: FOC-Grant` | No header was sent. |
| `403` | The header was refused. The body gives the reason, such as `The request has expired, or is valid for too long`. |
| `404` | The provider does not hold this piece in a restricted data set. |

## Limits

* **A claim cannot be revoked before it expires.** Set `expires` no later than you are willing to let it run. For a session key, use the session key's expiry.
* **Access control does not protect the key.** A reader who has decrypted a piece can share its contents, and a delivery's key keeps decrypting after its claim expires. Only fetching stops.
