Today anyone can fetch any piece, and [encryption](/developer-guides/encryption/encrypt-a-file/) is what keeps data private.
:::

Encryption decides who can *read* a piece. Read ACL will decide who can *fetch* it. This adds what keys alone cannot:

- **Expiry:** access ends at a set time, whereas a shared key never stops working (clients cannot 'unsee' what they have already decrypted, but they can't fetch more/newer data).
- **Private ciphertext:** someone who may not fetch a piece cannot get its bytes.

## Claim chains

Access is described by a **claim chain**, using exactly the same keyspaces, scopes and pieces as encryption [grants](/developer-guides/encryption/share-encrypted-data/). This ensures that read ACL and encryption key access stay in sync, enabling applications fine-grained control over what is shared, with whom, without adding another layer of complexity.

Importantly, clients can be issued the **grant** and **claims** in a single package called a **delivery**, so the recipient gets both the **permission** to fetch and the **key** to decrypt in one coherent package which they can save in their session. However when fetching from a server the key is detached so that the data remains secret from the SP.

The chain:

1. The owner's wallet signs the root claim: this bearer may fetch **this part** of the keyspace until **this time**, and onwardly delegate **this many more levels**.
2. Each bearer may onwardly delegate access to the same or narrower scope by signing a new claim for their delegate.
3. The final bearer signs each request to prove they are the legitimate holder of the credential. The provider checks the chain against the piece's FEE envelope metadata, with no on-chain lookups required.
4. The application formats the entire chain into an Auth Header for the GET request

## Issue access to a session key

The owner signs a root claim for the session key, which requires one wallet prompt beyond deriving the keyspace key. [`rootClaim()`](/reference/filoz/keysmith/functions/rootclaim/) returns the key for the claimed node, which is then wrapped.

```ts twoslash
// @lib: esnext,dom
import * as Keysmith from '@filoz/keysmith'
import { calibration } from '@filoz/synapse-sdk'
import type { Address, Hex } from 'viem'
import { privateKeyToAccount } from 'viem/accounts'

const account = privateKeyToAccount('0x...')
declare const keyspaceKey: Uint8Array
declare const ref: Keysmith.KeyspaceRef
declare const sessionAddress: Address
declare const sessionPublicKey: Hex
// ---cut---
const { chain, nodeKey } = await Keysmith.rootClaim(account, {
  ...ref,
  chainId: BigInt(calibration.id),
  kk: keyspaceKey,
  node: 'scope:agent-memory',
  bearer: sessionAddress,
  maxDepth: 1, // the session key may delegate one more level
  expires: Math.floor(Date.now() / 1000) + 24 * 60 * 60, // unix seconds
})
const grant = await Keysmith.wrapTo(sessionPublicKey, nodeKey, Keysmith.grantDescriptor(ref, 'scope:agent-memory'))
const delivery = Keysmith.encodeDelivery(chain, grant)
```

## Receive and delegate

[`openDelivery()`](/reference/filoz/keysmith/functions/opendelivery/) checks the chain's signatures, expiry and scope narrowing, and that the key matches the commitment its issuer signed.

A bearer with room to delegate (ie `maxDepth` is greater than the current length of the chain) can then sign a claim for a narrower scope, for example for a sub-agent working in a subdirectory or lower level of privilege. It can never widen access or extend the owner's expiry.

```ts twoslash
// @lib: esnext,dom
import * as Keysmith from '@filoz/keysmith'
import type { Address, Hex } from 'viem'
import { privateKeyToAccount } from 'viem/accounts'

const sessionPrivateKey: Hex = '0x...'
const sessionAccount = privateKeyToAccount(sessionPrivateKey)
declare const delivery: Uint8Array
declare const expected: Keysmith.KeyspaceRef
declare const agentAddress: Address
declare const agentPublicKey: Hex
// ---cut---
const { key, claim, chain } = await Keysmith.openDelivery(sessionPrivateKey, delivery)
if (claim.owner.toLowerCase() !== expected.owner.toLowerCase() || claim.keyspace !== expected.keyspace) {
  throw new Error('This delivery is for another keyspace')
}

const { chain: next, nodeKey } = await Keysmith.delegateClaim(sessionAccount, chain, {
  parentKey: key,
  node: 'scope:agent-memory/notes',
  bearer: agentAddress,
  maxDepth: 0,
})
const agentGrant = await Keysmith.wrapTo(
  agentPublicKey,
  nodeKey,
  Keysmith.grantDescriptor(claim, 'scope:agent-memory/notes'),
)
const agentDelivery = Keysmith.encodeDelivery(next, agentGrant)
```

## Fetch a gated piece

The final bearer signs a short-lived request for one piece and sends it, with the chain, in the `Authorization` header.

```ts twoslash
// @lib: esnext,dom
import * as Keysmith from '@filoz/keysmith'
import type { PieceCID } from '@filoz/synapse-sdk'
import { privateKeyToAccount } from 'viem/accounts'

const agentAccount = privateKeyToAccount('0x...')
declare const chain: Keysmith.ClaimChain
declare const pieceCid: PieceCID
declare function base64url(bytes: Uint8Array): string
// ---cut---
const request = await Keysmith.signRequest(agentAccount, chain, {
  pieceCid: pieceCid.bytes,
  expires: Math.floor(Date.now() / 1000) + 120,
})
const header = `FOC-Grant ${base64url(Keysmith.encodePresentation(chain, request))}`
```

The provider checks the presentation against the piece's envelope with [`verifyPresentation()`](/reference/filoz/keysmith/functions/verifypresentation/), which throws with the reason for any refusal.

## Limits

- **Claims expire but cannot be revoked early.** Revoking a session key stops its writes, not its fetching, until the claim expires. Keep expiries short if that window matters.
- **A claim is not a key.** A shared key stays shared; a claim only limits who can fetch the ciphertext.

For API details, see [Keysmith](/reference/filoz/keysmith/toc/).
